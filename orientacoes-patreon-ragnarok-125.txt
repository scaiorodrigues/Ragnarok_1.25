ORIENTAÇÕES PARA ESTRUTURAÇÃO DE PATREON
Projeto: Ragnarok 1.25 (Fork rAthena – Hardcore Pre-Renewal)
Documento de apoio – uso interno / referência
================================================================================

OBJETIVO DESTE DOCUMENTO
------------------------
Fornecer diretrizes práticas para montar um Patreon (ou plataforma similar)
de apoio ao desenvolvimento do projeto de forma mais defensável, reduzindo
riscos relacionados a:

  • Violação de propriedade intelectual (Gravity / NCSoft)
  • Políticas de uso do Patreon
  • Exposição desnecessária do projeto a denúncias

Este documento NÃO é aconselhamento jurídico. É uma orientação prática
baseada em riscos conhecidos da comunidade de emuladores.

================================================================================
1. POSICIONAMENTO GERAL (O MAIS IMPORTANTE)
================================================================================

Evite posicionar o projeto como:

  ✗ “Servidor de Ragnarok Online”
  ✗ “Meu servidor privado de RO”
  ✗ “Atualizações do Ragnarok 1.25”
  ✗ “Suporte ao servidor hardcore de Ragnarok”

Prefira posicionamentos genéricos e técnicos:

  ✓ “Desenvolvimento de sistemas hardcore para emuladores rAthena”
  ✓ “Modificações e ferramentas open-source para emuladores Pre-Renewal”
  ✓ “Pesquisa e desenvolvimento de mecânicas hardcore em emuladores MMORPG”
  ✓ “Fork experimental de rAthena com foco em morte permanente e economia simulada”

Regra de ouro:
  Quanto menos você associar o nome comercial “Ragnarok Online” e a identidade
  visual oficial ao pedido de dinheiro, menor o risco de denúncia e de ação
  da plataforma ou dos detentores da IP.

================================================================================
2. NOME E DESCRIÇÃO DO PATREON
================================================================================

Sugestões de nome (escolha um neutro):

  • Dev Hardcore Emulator
  • PreRE Hardcore Systems
  • Athena Hardcore Lab
  • Open Hardcore Emulator
  • Sistemas Hardcore rAthena

Descrição recomendada (exemplo):

  “Apoio ao desenvolvimento de modificações open-source para emuladores
   rAthena com foco em mecânicas hardcore (morte permanente, economia
   simulada por bots, sistemas de progressão experimental).

   Todo o código permanece sob licença GPLv3 e é disponibilizado publicamente.
   Este espaço existe apenas para apoiar o tempo de desenvolvimento, testes
   e manutenção do projeto experimental.”

Evite na descrição:

  • Uso de “Ragnarok Online”, “RO”, “Gravity”, “oficial”
  • Promessas de “servidor online”, “jogue agora”, “client pronto”
  • Imagens oficiais, logos, screenshots com UI/sprites reconhecíveis
  • Menção a monétização in-game (VIP, cash, itens)

================================================================================
3. O QUE OFERECER NOS TIERS (E O QUE NÃO OFERECER)
================================================================================

O que é relativamente mais seguro oferecer:

  • Acesso antecipado a builds / commits experimentais
  • Changelog detalhado e explicações técnicas
  • Prioridade em sugestões de mecânicas (sem garantia de implementação)
  • Documentação extra, diagramas de sistemas, guias de compilação
  • Canal de discussão técnica (Discord/Telegram fechado)
  • Reconhecimento no README ou AUTHORS (se quiser)
  • Relatórios de progresso mensais

O que deve ser EVITADO:

  ✗ Acesso a servidor privado rodando
  ✗ Client completo / hexed / assets
  ✗ Contas, itens, zeny, VIP ou qualquer vantagem in-game
  ✗ “Slots prioritários” em servidor
  ✗ Distribuição de material protegido por copyright
  ✗ Uso de marcas registradas da Gravity

Regra prática:
  Ofereça valor sobre o CÓDIGO e o DESENVOLVIMENTO, nunca sobre a experiência
  de jogar Ragnarok Online.

================================================================================
4. ESTRUTURA SUGERIDA DE TIERS
================================================================================

Tier 1 – Apoiador (R$ 5 ~ 15)
  • Acesso ao changelog detalhado
  • Atualizações de progresso
  • Nome listado como apoiador (opcional)

Tier 2 – Desenvolvedor Apoiador (R$ 25 ~ 40)
  • Tudo do anterior
  • Acesso antecipado a builds experimentais
  • Canal de discussão técnica
  • Prioridade em feedback de mecânicas

Tier 3 – Patrocinador Técnico (R$ 60+)
  • Tudo do anterior
  • Relatório técnico mensal mais aprofundado
  • Possibilidade de sugerir experimentos de sistemas
  • Crédito destacado no repositório (se desejado)

Mantenha os valores modestos no início. Não prometa volume de atualizações
que você não consiga cumprir.

Este espaço existe para apoiar o desenvolvimento de um fork experimental
do emulador rAthena focado em mecânicas hardcore e sistemas de economia

================================================================================
6. BOAS PRÁTICAS DE SEGURANÇA E REDUÇÃO DE RISCO
================================================================================

1. Nunca distribua client, sprites, mapas ou qualquer asset oficial.
2. Não use o nome “Ragnarok Online” de forma comercial ou proeminente.
3. Mantenha o repositório sempre sob GPLv3 e com o código público.
4. Evite screenshots que mostrem a interface oficial do jogo.
5. Não prometa “servidor online” ou “comunidade para jogar”.
6. Separe claramente: desenvolvimento de software ≠ operação de servidor.
7. Se for operar um servidor próprio, trate-o como atividade separada
   e não vincule o Patreon diretamente a ele.
8. Considere usar GitHub Sponsors ou Ko-fi como alternativas (ou em paralelo),
   pois algumas pessoas consideram o risco de plataforma diferente.
9. Tenha um plano B: se o Patreon for denunciado, você já sabe para onde
   migrar a comunicação com os apoiadores.
10. Documente tudo como “pesquisa / experimento de sistemas de emulador”.

================================================================================
8. OBSERVAÇÃO FINAL
================================================================================

Mesmo seguindo todas as orientações acima, o risco nunca é zero.
Servidores e projetos ligados à propriedade intelectual de Ragnarok Online
existem em uma zona cinzenta há muitos anos. Monetizar qualquer coisa
relacionada aumenta a visibilidade e o interesse de denúncias.

A abordagem mais prudente é:

  • Tratar o projeto como desenvolvimento de software open-source
  • Oferecer valor técnico (código, documentação, experimentos)
  • Evitar qualquer associação comercial com a experiência de “jogar RO”

Se o projeto crescer bastante, reavalie periodicamente a exposição.
